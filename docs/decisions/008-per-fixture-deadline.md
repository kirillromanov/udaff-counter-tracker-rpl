# Per-fixture prediction deadline

Recorded 2026-11-20. A participant may post one fixture at a time and may revise a fixture by posting another comment. The revision counts only when its publication time is strictly before that fixture's kickoff. The same comment can be eligible for a later fixture and ineligible for one that has already kicked off.

Kickoff lines in the article have no offset. `readFixtureLine` treats those digits as the forum site clock and stores one UTC instant. A read-only copy of round 15's article shows `20.11, 19:30 — Ростов — Крылья Советов`, and the stored kickoff is `2026-11-20T16:30:00.000Z`. The deadline does not convert a stored kickoff again.

The HTML permalink `dd/mm/yyyy at hh:mm` also has no offset. The WordPress REST schema calls `date` the site timezone and `date_gmt` GMT. Read-only responses for comments in July, August, October, and November differ by exactly three hours, and the permalink minute matches `date`, not `date_gmt`. The page has no `<time datetime>` on the permalink and no browser timezone script. `FORUM_SITE_OFFSET_MINUTES` is 180. A new permalink is converted to UTC once. An explicit `Z` or `±hh:mm` offset is used as given and is not shifted again. `createdAt`, `lastFetchedAt`, and the import clock are not eligibility. A body `<del datetime>` is not a publication time.

A legacy `postedAt` is the permalink minute stored as UTC. The live slip shows that encoding as time uncertain and does not accept or reject the prediction. The raw permalink remains in `rawHtml`. No schema column is required to tell the encodings apart. Round 15 is the one corrected round: each of its 14 comments had an offset-less permalink for its own comment id, and `postedAt` matched the digits read as UTC, so those rows were set to the same minute read as UTC+3. Seconds were not invented. Comments on rounds 1–14 were not rewritten, and their saved calculations stay on the stored breakdown.

A later eligible comment replaces only the fixtures named in that comment. An earlier eligible prediction for any other fixture stays. A comment published at the kickoff instant, or after it, does not replace that fixture. Identical eligible scores stay on the earliest comment. Two eligible comments with the same publication time and different scores stay in review. A line with no publication time, a legacy offset-less `postedAt`, or a fixture with no kickoff stays in review and does not replace an eligible line. A manual set remains the whole slip.

Archived rounds, closed rounds, and rounds whose status is `scored` present the saved calculation. The review cell, its points, and the results and export totals come from that round's stored breakdown. A saved miss stays empty. A current candidate is labeled separately and is not written into the saved cell. An open or partial production round keeps live selection, including a fixture that was not part of a stored partial score. Recalculation remains a separate explicit action.

Editing a stored comment is not authorized by its original publication time. `commentEditEvidence` reads only the HTML before the first paragraph. An edit time counts when that metadata has an edit mark and exactly one timestamp different from publication. The permalink time is not an edit time. A reliable edit writes only the incoming fixtures whose edit time is before kickoff and leaves every other stored prediction. A comment whose body differs from the parsed slip, and which has no reliable edit time, is flagged and its prediction rows are not replaced. A stored `updated` label is not that difference. The edit time is derived from stored `rawHtml` when the slip is read, so the rule does not add a schema column.

Late lines remain stored. They are omitted from the effective slip. An unresolved cell is omitted from intermediate scoring. A fixture with only a late line is missing and can take the existing missing penalty once the result is finished.

A second read-only comparison on the same snapshot, after saved and live views were separated, found no saved cell that disagreed with its stored breakdown on rounds 1–14. Closed round 14 and archived round 13 are manual, so their candidate slips stay on those manual selections. Auto rounds 1–12 have legacy publication times, so their current candidates are uncertain or absent; they are not classified as late. Those historical `postedAt` values were left as stored.

On an isolated copy, correcting the 14 round-15 times changed that round's live cells from 58 time-uncertain and 14 missing to 58 accepted, 0 uncertain, 0 late, 0 ambiguous, and 14 missing. The accepted scorelines are the same 58 that the earlier selection used. No comment falls in a kickoff minute. The latest corrected instant is `2026-11-19T18:55:00.000Z`, before the first kickoff `2026-11-20T16:30:00.000Z`. The live write changed only those `postedAt` values. Prediction rows, manual selections, kickoffs, `nextPredictionFetchAt`, result attempts, scores, and other rounds were unchanged.
